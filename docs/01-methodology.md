## 1.1. Общая схема

Исследование проходило в четыре итерации, каждая — с нарастающим усложнением
инструмента:

| # | Вопрос | Метод | Результат |
|---|--------|-------|-----------|
| 1 | Кто у кого перепечатывает (RU↔RU) | TF-IDF + Jaccard по трёхсловным шинглам | [02-crossposting-ru.md](02-crossposting-ru.md) |
| 2 | Есть ли зарубежные каналы и крадут ли их | мультиязычные эмбеддинги RU↔EN | [03-foreign-channels.md](03-foreign-channels.md) |
| 3 | Откуда русские берут новости | исходящие ссылки, @упоминания, форварды | [04-source-map.md](04-source-map.md) |
| 4 | А не раньше ли новость была где-то ещё | Hacker News API как внешний прибор | [05-timing.md](05-timing.md) |

Итерация 4 существовала потому, что итерации 1–3 измеряли **структуру связей**, но
не измеряли **время**. Это принципиальная разница, и она привела к исправлению
выводов — см. [06-errors-and-corrections.md](06-errors-and-corrections.md).

## 1.2. Сбор данных: механика краулера

### Источник

Публичный веб-превью Telegram: `https://t.me/s/<username>`. Работает без авторизации,
отдаёт до 20 постов на страницу.

### Пагинация

В HTML есть мета-тег пагинации:

```html
<a href="/s/technomedia?before=15112" class="tme_messages_more" data-before="15112">
```

Алгоритм: взять `data-post` последнего (минимального по id) поста на странице,
подставить как `?before=`, повторить. Условие остановки — самая ранняя дата на
странице вышла за нижнюю границу окна.

### Разбор поста

Селекторы, которые реально работают:

```python
# Ключевой факт: data-post лежит на ВНУТРЕННЕМ div, а не на обёртке wrap.
# Первые версии краулера читали data-post с .parent и получали 0 постов.
```

### Известная ловушка: страницы не отсортированы по дате

`t.me/s/` отдаёт посты **не в хронологическом порядке** даже внутри одной страницы.
Проверено на `@tlive` (10 постов на страницу):

```
page 1 dates: 2026-09-22, 2026-09-22, 2026-09-23, 2026-09-24, 2026-09-24 ...
```

Первая версия краулела делала `if dt < SINCE: return` на первом же старом элементе
и теряла весь остаток страницы. Правильно — обработать страницу целиком, а решение
о выходе принимать по `min(dts) < SINCE`.

## 1.4. Слой 1: дословные совпадения (Jaccard по шинглам)

Метод из `tools/analyze2.py`.

```python
def shingles(text, n=3):
    w = text.split()
    return set(" ".join(w[i:i+n]) for i in range(len(w)-n+1))

def jaccard(a, b):
    return len(a & b) / (len(a) + len(b) - len(a & b))
```

- Порог кластеризации: **Jaccard ≥ 0.55**
- Кандидаты генерируются inverted-index по шинглам (шары > 60 отбрасываются как
  слишком частые)
- Перед кластеризацией тексты нормализуются: lowercase, ссылки вырезаются,
  пунктуация и всё неалфавитное заменяется пробелом

**Что метод ловит:** дословное копирование, клоны, зеркала.
**Чего не ловит:** пересказ. Массовые русские каналы именно переписывают, поэтому
для них метод даёт заниженные ~1%.

## 1.5. Слой 2: смысловые совпадения (TF-IDF)

```python
vec = TfidfVectorizer(analyzer="word", ngram_range=(1, 2),
                      sublinear_tf=True, max_features=200000)
X = normalize(vec.fit_transform([norm(p["text"]) for p in posts]))
S = (X @ X.T).toarray()
```

- Порог ребра: **cosine ≥ 0.42**
- Union-Find по рёбрам → кластеры ≥ 2 постов
- Диагональ и внутриканальные пары обнуляются

**Замер разделения.** На реальных данных:

| Порог | Пар найдено | Интерпретация |
|-------|-------------|----------------|
| 0.9–1.0 | 22 | фактически идентичный текст |
| 0.8–0.9 | 107 | очень близкий текст |
| 0.7–0.8 | 294 | та же новость, пересказ |
| 0.6–0.7 | 1800 | та же тема |
| 0.5–0.6 | 9901 | **шум** — тематическое совпадение, не новость |
| 0.4–0.5 | 42 124 | **полный шум** |

**Практический вывод, который определил всю дальнейшую работу:** порог 0.55 даёт
5301 кросс-пар, из которых почти все — мусор. `@tldrtech` «совпадал» с 356 русскими
постами на среднем 0.614, потому что у него 500 постов в неделю на все темы сразу.
Реальные кросс-пары лежат в диапазоне **0.80–0.96**. Все итоговые выводы по
кросс-бордеру сделаны на пороге 0.80.

Метод из `tools/cross2.py`. Обязателен, потому что RU↔EN не пересекается ни по

Перед применением метод проверен на двух вручную подобранных парах:

| Пара | cosine |
|------|--------|
| RU: «Релиз GPT-6.1 Sol: новая модель OpenAI для кодинга, в 5 раз дешевле» ↔ EN: «OpenAI released GPT-6.1 Sol, a new coding model that is 5x cheaper» | **0.937** |

## 1.7. Слой 4: измерение времени (Hacker News как прибор)

Метод из `tools/timeline3.py`. Появился после того, как выяснилось, что слои 1–3
ничего не говорят о времени появления новости.

### Что использовалось

```python
# Hacker News — Algolia API, полный архив, точные UNIX-таймстемпы
GET https://hn.algolia.com/api/v1/search_by_date
    ?query=<q>&tags=story&hitsPerPage=60
→ hits[].created_at_i
```

### Что отбраковано и почему

| Источник | Статус | Причина |
|----------|--------|---------|
| Hacker News (Algolia) | **пригоден** | Полный архив, точные таймстемпы, чистые заголовки |
| Google News RSS | отбракован | Отдаёт прогнозы Polymarket, записи из прошлого и **будущие** даты (Diden: 30.09 при русском посте 28.09). Семантически смежные статьи, а не та же новость |
| RSS OpenAI (`openai.com/news/rss.xml`) | отбракован | `pubDate` — круглые заглушки: «Introducing dots» = `00:00 GMT`, «Introducing GPT-6.1 Sol» = `10:00 GMT`, хотя DevDay шёл в ~17:00 UTC |
| X / Twitter | **недоступен** | `cdn.syndication.twimg.com` → 0 байт; Nitter мёртв |
| Reddit JSON | недоступен | HTTP 403 |
| Bluesky | недоступен | HTTP 403 |
| Mastodon | недоступен | HTTP 404 |
| TechCrunch / Verge / Ars / MITTR RSS | частично | Работают, но держат только ~20 последних элементов — пригодны лишь для новостей 29.09 |
| VentureBeat RSS | отбракован | HTTP 429 (rate limit) |

### Отбор новостей

Ручной, из верифицированных кластеров — **не** регулярками по ключевым словам.
Первая версия использовала `re.search` и матчила не то: запрос «ChatGPT $500 tier»
поймал пост от 18 февраля, «Starship orbit» — предзапусковые анонсы. 6 из 12 историй
оказались не тем же событием.

**Итог: 6 сопоставимых историй из 12.** Все цифры в [05-timing.md](05-timing.md)
опираются только на эти шесть.

### 1.10.1. Критическая оговорка о происхождении выборки

**Критерий отбора 22 русских каналов не формализован.** Каналы
накапливались в ходе нескольких разведочных обходов ниши
(см. [04-source-map.md](04-source-map.md)) и в окончательный список
попали те, кто уже представлял интерес к моменту отбора.

Из этого следуют три ограничения, которые обязательны для любых выводов:

1. **Смещение по удобству.** Вероятен перекос в сторону каналов,
   которые легче нашлись через каталоги и подборки. Каналы, существующие
   только «внутри» ниши, в выборку не попали.
2. **Смещение по активности.** Отбирались каналы, публиковавшие
   в момент обхода, — то есть не замершие.
3. **Зависимость наблюдений.** Каналы не независимы: они перепечатывают
   друг друга (см. [02-crossposting-ru.md](02-crossposting-ru.md)),
   делят аудиторию и источники. Любая корреляция между каналами
   завышена.

> **Следствие для отчётности.** «Дециль ниши» в
> [09-behavioral.md](09-behavioral.md) §8.3 — это дециль **этой
> выборки**, а не ниши. Порог завышен с неопределённой величиной.
> Для корректной оценки нужен стратифицированный случайный отбор
> из кадрового множества в 921 канал, уже собранного
> в `data/market_size.json`.

### 1.10.2. Замещение подписчиков и дрейф метрик

Подписчики снимаются **один раз** — на дату сбора. Любая метрика
 вида «реакций / подписчиков» или «просмотров / подписчиков»
поэтому **смещена для постов, опубликованных задолго до сбора**.

Измерено (`tools/stats_audit.py` §6): положительная корреляция между
возрастом поста и `rx_1k` в **16 из 20** каналов, тогда как для
`rx/просм` она около нуля (от −0.20 до +0.28).

**Правило проекта:** метрики со знаменателем «подписчики»
не использовать для сравнения каналов с разным горизонтом
наблюдения. Основная метрика поведенческого анализа —
**отношение двух накопительных счётчиков** (`rx/просм`).

### 1.10.3. Глубина выборки различается и смешана с частотой

Краул идёт ровно 12 страниц на канал. Поэтому:

| Тип канала | Постов/сутки | Глубина выборки |
|---|---|---|
| массовый | 13–19 | **≈ 11 суток** |
| экспертный | 1–7 | **до 168 суток** |

Возраст поста и частота канала **перепутаны**: быстрые каналы дают
только свежие посты, медленные — преимущественно старые.

**Правило проекта:** любое сравнение, где участвует и возраст,
и частота, должно контролироваться либо внутриканально
(§1.11.2), либо через явную фильтрацию по возрасту с оговоркой,
что фильтр сам смещён по частоте.

### 1.10.4. Реакции: откуда берутся и в чём их предел

Публичное превью Telegram отдаёт блок реакций, состоящий из
фишек вида [эмодзи] + число. **Элемента «всего реакций» в блоке нет**,
итог получается суммированием. Кастомные (анимированные) эмодзи
отдаются как `<tg-emoji emoji-id="...">` **без текста** и требуют
отдельной обработки.

Telegram показывает не более **~12 типов реакций** на пост;
в выборке 71 пост (1.7 %) достигает предела. Для них суммарное
`rx` — **нижняя оценка**.

`rx` — сумма эмодзи, а не число проголосовавших: один человек,
поставивший три разных эмодзи, учитывается трижды. Для контроля
в проекте введён прокси **`votes` = максимальная фишка** — приближение
к числу уникальных голосовавших.

**Сбор реакций требует последовательных запросов.** При
параллелизме > 1 и задержке < 1 с Telegram отдаёт страницы
**с пустыми блоками реакций** (см. [06](06-errors-and-corrections.md) §2.8).
Рабочая конфигурация: `MAX_WORKERS = 1`, задержка 2 с.

## 1.11. Статистический протокол

> Этот раздел добавлен после аудита
> [10-statistical-audit.md](10-statistical-audit.md). До него
> в проекте не было ни одного доверительного интервала, ни одной
> поправки на множественные сравнения и ни одного контроля
> парадокса Симпсона. Ниже — обязательные правила.

### 1.11.1. Перед сбором

| Шаг | Проверка |
|---|---|
| Зафиксировать критерий отбора объектов | записать в документ |
| Посчитать мощность под ожидаемый эффект | `min_detectable_rho(n)`; если эффект слабее порога — увеличить выборку или признать вопрос неразрешимым |
| Предрегистрировать пороги | кластеры, децили, темы — либо пометить анализ как разведывательный |
| Определить целевую функцию задачи | какая величина оптимизируется: отклик на пост, суммарный отклик, охват, выручка |

### 1.11.2. Правильный оценщик для причинного вопроса

**Различать три типа вопросов и три типа дизайна:**

| Вопрос | Пример | Правильный дизайн |
|---|---|---|
| Описательный | «какие каналы в нише активнее» | сравнение объектов между собой |
| Ассоциативный | «какие посты лучше работают» | **внутриобъектный**: свой топ против своего низа |
| **Причинный** | «что будет, если я изменю своё поведение» | **внутриобъектный во времени**: свои же дни против своих же дней |

> **Типичная ошибка проекта.** Вопрос «сколько мне постить в сутки» —
> причинный по природе (действие нашего канала), но был оценён
> сравнением 20 чужих каналов между собой. Результат завысил
> эффект в **4.2 раза** (−0.662 вместо −0.159).
>
> **Правило:** если решение касается нашего собственного действия,
> оценщик должен быть внутриобъектным во времени.

### 1.11.3. Обязательные элементы каждой метрики

Без этих пяти элементов число не публикуется:

1. Точечная оценка
2. **95 % доверительный интервал**
3. p-значение либо (для корреляций) сам интервал
4. Размер выборки
5. **Что не контролировалось**

### 1.11.4. Обязательные проверки перед выводом

1. **Парадокс Симпсона.** Есть групповая переменная → считать
   частичную корреляцию **и** внутригрупповую отдельно.
   Грубая корреляция **сильнее** обеих внутригрупповых — признак
   межгруппового смешения, а не сильного эффекта.
2. **Чувствительность к пропускам.** Пересчитать ключевые числа при
   каждом разумном правиле обработки. Меняется знак или значимость —
   **число нерепортируемо**. (Проверка выявила: rho −0.662 → −0.378
   с интервалом, пересекающим ноль, в зависимости от включения двух
   каналов.)
3. **Дрейф метрики.** Метрика со знаменателем, растущим со временем,
   проверяется корреляцией с возрастом объекта.
4. **FDR** на любое семейство тестов. Сообщать: «пережило K из N».
5. **TOST** для любого «нулевого» вывода. Отсутствие значимости
   не означает отсутствия связи — нужна граница эквивалентности.
6. **Кластеризация** по повторяющимся единицам (сюжет, автор, событие)
   с расчётом дизайн-эффекта.
7. **Проверка на артефакт определения.** Например, гипотеза
   «разрыв слоёв = разные реакционные привычки» проверяется заменой
   суммы эмодзи на максимальную фишку. Разрыв 5.69 → 5.07 —
   гипотеза **не подтвердилась**, но сам разрыв устоял.

### 1.11.5. Язык выводов

| Запрещено | Требуется |
|---|---|
| «связи нет» при p > 0.05 | «не обнаружена при мощности X» |
| «влияет», «вызывает» для наблюдательных данных | «сопровождается», «ассоциировано» |
| «значимо» без интервала | интервал обязателен |
| «×2 выигрывает» без указания поддиапазона | к чему относится коэффициент |
| «сильнейшая связь» без проверки Симпсона | сначала частичная корреляция |
| «работает / не работает» | «переживает / не переживает FDR» |
| «дециль ниши» по удобной выборке | «дециль выборки из N каналов» |
| рекомендация без целевой функции | назвать оптимизируемую величину |

### 1.11.6. Обязательная структура итогового документа

1. Что измерено и как (сценарий)
2. **Размер выборки и его источник**
3. **Критерий отбора объектов**
4. Определения всех метрик
5. Оценки **с интервалами**
6. **Что не контролировалось**
7. **Известные смещения метрик**
8. Поправка на множественные сравнения при их наличии
9. **Какие выводы отозваны** и почему
10. **Внешняя валидность**: кому применимо, кому нет

## 1.12. Воспроизведение

```powershell
cd parser

# 1. Обнаружение живых зарубежных каналов (фильтр по свежести последнего поста)
$env:PYTHONIOENCODING='utf-8'; python tools/probe2.py
$env:PYTHONIOENCODING='utf-8'; python tools/probe3.py

# 2. Сбор постов RU (неделя) и EN
$env:EN_ONLY='';  python tools/crawl.py
$env:EN_ONLY='1'; python tools/crawl.py

# 3. Сбор ссылок/упоминаний/форвардов (2 недели)
python tools/crawl_links.py

# 4. Анализ
python tools/analyze2.py     # RU↔RU кластеры
python tools/cross2.py       # RU↔EN эмбеддинги
python tools/sources3.py     # карта источников
python tools/timeline3.py    # таймлайн по Hacker News
```

Зависимости: `python 3.11`, `requests`, `beautifulsoup4`, `scikit-learn`,
`sentence-transformers` (модель скачивается при первом запуске `cross2.py`).

**Окна заданы константой `SINCE` внутри `crawl.py` и `crawl_links.py`.** Для
перезамера на другом периоде менять нужно именно её.
